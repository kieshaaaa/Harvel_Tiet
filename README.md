
# HARVELL: Hardware Analysis Reverse engineering of VErilog using LLMs
***Modern computer architecture is moving towards a co-processor centric design. Field-Programmable Gate Arrays (FPGAs) are one of the key elements in this architecture for the following reasons; (a) FPGAs provide flexibility and Reconfigurability along with parallel processing capabilities which is useful to achieve higher performance and low latency, (b) Customizability of FPGAs can be useful for prototyping and development both and escpecially useful in industries where long product lifespan is required (e.g. aerospace, automotive, defense, industrial automation, etc., (c) FPGAs can implement secure hardware functions, such as encryption and secure boot, making them valuable for applications that require strong security measures. They can also be used to develop custom security features that are difficult to replicate or tamper with. Majoritiy of FPGA equipped devices are shipped with a proprietary FPGA hardware-specific compiler that converts the high-level programs (e.g. C, C++, Rust, etc.) to equivalent Verilog/VHDL executable. Since most of the compilers (e.g., Xilinx SDNet, Netronome SDK, Barefoot Capilano, etc.) are commercial tools and are closed source, the verification of the final VHDL executable is difficult. In this case, verification of FPGA compliant programs and identification of security loopholes is one of the significant challenges.***

***Our objective in this work is to design and develop a Reverse HLS framework that can generate profiles for the closed source compilers. We also aim to design a separate framework for the generation of the “reverse compiler” from the profile information of the closed source compiler. The proposed reverse compiler should be able to produce equivalent high-level programs from the platform-specific executable; thus can ease the security analysis and debugging of both the closed source compilers and FPGA compliant programs. This proposed framework can also help in the democratization of FPGA-compliant appication development by enabling community developers to design their wrapper compilers and feature augmentation without the help of the proprietary compiler developer support. This research work is being pursued jointly between the “NIL@CENCCOM”, “AL & ML Lab” from the “Center for AI & ML”, and the “Ethical Hacking Lab” from the “Center for Cyber Security and Data Privacy.”***

### Prerequisites   
Before you begin, ensure you have met the following requirements:    
* Tools: Xilinx Vitis HLs, fairseq
* Software: Python 3.9, pip, gcc, clang-format
* Libraries: torch, tensorboardX, omegaconf, hydra-core, numpy, bitarray, tqdm, scikit-learn, sacrebleu
   
1. Ensure Python and pip are Installed

   First, make sure you have Python installed on your system. This project requires Python 3.x. You can check your Python version by running:
   ```   
   python --version
   ```   
   ```   
   pip --version
   ```   
### Installation
   
1. Clone the Repository
   
   Start by cloning the repository to your local machine:
   ```   
   git clone https://github.com/subhrendu1987/Reverse-Engineering.git   
   cd Reverse-Engineering
   ```   
2. Set Up Your Environment   
   
   Provide instructions on setting up the environment. This might include creating virtual environments, installing dependencies with a package manager.
   ```   
   sudo apt install python3.9-venv   
   ```
   ```  
   # Create a virtual environment using Python 3.9
   python3.9 -m venv <myenv_name>
   ```   
   ```   
   # Activate the virtual environment
   source <myenv_name>/bin/activate
   ```   
3. Installing dependencies   

   ```   
   # Navigate to the Reverse-Engineering project   
   cd Reverse-Engineering   
   
   # installl the dependencies in the provided Requirement.txt file
   pip install -r Requirements.txt   
   ```   
   
### Running the Project   
    
1. Execute the custom preprocessing on the orignal C codes.    
   ```   
   # Navigate to the RevEngg_Project_Codes      
   cd Reverse-Engineering/RevEngg_Project_Codes    
   # Run a custom preprocessing python code for only one folder which carry the c code files of one c program    
   python3 preprocess_C_.py -in_f <path/of/c-code/input_folder> -out_f <path/of/output_folder> -db    
   ```   
   Example: we did it for all the c programs which is in the seperate one folder in the root folder name [All_c_code_plus_selenium_c_1379_folder](./All_c_code_plus_selenium_c_1379_folder)   
   ```   
   find ./Reverse-Engineering/RevEngg_Project_Data/All_c_code_plus_selenium_c_1379_folder -maxdepth 1 -type d -exec python3 preprocess_C_.py -in_f {} -out_f ./Reverse-Engineering/RevEngg_Project_Data/Output/All_c_code_plus_selenium_preprocess_custom -db \;     
   ```   
   
2. Execute the conversion of the c codes into the verilog codes.      
   ```   
   # Run a bash script to convert the c codes into the verilog code using the Xilinx Vitis HLS   
   bash c_to_v.sh <PATH/OF/C-CODE/FILE> <PATH/OF/OUTPUT/FOLDER>   
   ```   
   Example: we did it for all the c file which is in the folder name [All_c_code_plus_selenium_preprocess_custom](./Output/All_c_code_plus_selenium_preprocess_custom)    
   ```    
   find ./Reverse-Engineering/RevEngg_Project_Data/Output/All_c_code_plus_selenium_preprocess_custom -type f -name "*.c" -exec bash c_to_v.sh {} ./Reverse-Engineering/RevEngg_Project_Data/Dataset_verilog \;   
   ```   
      
3. Execute the custom preprocessing on the verilog codes        
   ```    
   # Run the custom preprocessing python code for only one folder which carry the verilog files of one verilog program   
   python3 preprocess_V.py -input_folder <PATH/OF/VERILOG_FOLDER> -output_folder <PATH/OF/OUTPUT_FOLDER>   
   ```   
   Example: we did it for all verilog folder which carry the verilog program   
   ```   
   find ./Reverse-Engineering/RevEngg_Project_Data/Dataset_verilog -maxdepth 1 -type d -exec python3 preprocess_V.py -input_folder {} -output_folder ./Reverse-Engineering/RevEngg_Project_Data/Dataset_verilog_final \;     
   ```   
    
### Transforming Raw Data into Actionable Insights and Achieving Model Excellence with Fairseq    
     
1. Data Setup:  
   ```  
   cd ./Reverse-Engineering/RevEngg_Project_Codes/RevEngg   
   
   python3 make_dataset.py -in_f_c <PATH/OF/C_DATA/INPUT_FOLDER> -in_f_v  <PATH/OF/VERILOG_DATA/INPUT_FOLDER> -out_f_src  <PATH/OF/.src/FILE> -out_f_tgt  <PATH/OF/.tgt/FILE>     
   ```   
   Example:   
   ```   
   python3 make_dataset.py -in_f_c ./Reverse-Engineering/RevEngg_Project_Data/dataset_clang_format -in_f_v  ./Reverse-Engineering/RevEngg_Project_Data/Dataset_verilog_final -out_f_src  /Reverse-Engineering/RevEngg_Project_Data/Consolidated_data_final/consolidated.src -out_f_tgt /Reverse-Engineering/RevEngg_Project_Data/Consolidated_data_final/consolidated.tgt   
   ```   
      
   Spliting the data into traning and testing format..   
   ```   
   python3 split.py -in_src_file </PATH/OF/.src/FILE> -in_tgt_file </PATH/OF/.tgt/FILE> -out_folder </PATH/OF/OUTPUT_FOLDER> -num_line <NUM_LINE>   
   ```   
   Example:   
   ```   
   python3 split.py -in_src_file ./Reverse-Engineering/RevEngg_Project_Data/Consolidated_data_final/consolidate.src -in_tgt_file ./Reverse-Engineering/RevEngg_Project_Data/Consolidated_data_final/consolidate.tgt -out_folder ./Reverse-Engineering/RevEngg_Project_Data/Consolidated_data_final_1375 -num_line 5    
   ```   
   
2. Tokenization and Vectorization with Fairseq   
   ```   
   fairseq-preprocess --source-lang src --target-lang tgt --trainpref ./Reverse-Engineering/RevEngg_Project_Data/Consolidated_data_final_1375/train --testpref ./Reverse-Engineering/RevEngg_Project_Data/Consolidated_data_final_1375/test --destdir ./Reverse-Engineering/RevEngg_Project_Data/fairseq_preprocess_data   
   ```   

3. Model Training/Testing    
   ```   
   fairseq-train --valid-subset train ./Reverse-Engineering/RevEngg_Project_Data/fairseq_preprocess_data --lr 0.01 --keep-last-epochs 1 --clip-norm 0.1 --dropout 0.0 --batch-size 50 --arch transformer --max-source-positions 19400 --max-target-positions 1024 --max-epoch 800 --encoder-attention-heads 16 --decoder-attention-heads 16 --save-dir ./Reverse-Engineering/RevEngg_Project_Data/fairseq_model/checkpoints --optimizer nag --tensorboard-logdir ./Reverse-Engineering/RevEngg_Project_Data/fairseq_model/logs    
   ```   

4. Comprehensive Evaluation    
   ```   
   fairseq-generate ./Reverse-Engineering/RevEngg_Project_Data/fairseq_preprocess_data --scoring wer --path ./Reverse-Engineering/RevEngg_Project_Data/fairseq_model/checkpoints/checkpoint_best.pt --batch-size 1 --source-lang src --target-lang tgt --max-source-positions 19400 | tee ./Reverse-Engineering/RevEngg_Project_Data/Results/aed.out   
   ```
